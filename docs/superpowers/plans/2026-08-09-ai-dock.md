# Ordinate — the AI dock

Build the dock: a docked, toggleable AI panel on the right edge that follows you across the app.
Explore is the blank-page mode — you pick a dataset and start cold. The dock is the contextual
mode: it already knows what you're looking at, and it can propose a change you apply with one
click.

Depends on feat/explore Phase 2. The dock reuses Explore's transcript renderer and its
explicit-context override. **Dependency verified: Phase 2 landed as `9e21d2a` ("make it ask —
dataset scope, model chip, grounded answers"). This branch is cut from it.**

## What this is not

- Not a second chat. Same conversation, same thread store, second container.
- Not an agent that acts on its own. Three fixed proposal types, each grounded, each reversible,
  each requiring a click.
- Not a place where a model produces a number. Proposals are structure; the app computes every
  value, exactly as it does today.

## Global Constraints

**Prefix `dk-` for DOM ids, `dk` for renderer globals.** Taken already:
`ds`/`dash`/`dc`/`an`/`viz`/`conn`/`cv`/`exp`/`ex`/`exec`/`ai`/`xp`. A collision silently breaks an
unrelated surface.

**Renderer mechanic — four steps per new file:** create `renderer/hub/<name>.ts` (classic global
scope, no import/export) → add `<script src="<name>.js">` to `index.html` in dependency order →
declare shared symbols in `globals.d.ts` → add the emitted sibling to the `.gitignore` entry.
Miss step 2 or 4 and the feature vanishes with no error. (Note: `feat/explore`'s own commit
records that step 3 is skipped in practice — the renderer is one shared global scope, so TS
already sees sibling top-level declarations and re-declaring them is a TS2451 double-declaration.
Only genuinely external globals belong in `globals.d.ts`. Follow that precedent.)

**CSP:** `default-src 'none'; style-src 'self'; script-src 'self'`. No inline `style=` in HTML —
`hub.css` classes only. Model output goes through `textContent`, never `innerHTML`.

**File size:** `.claude/rules/file-size.md` (500 soft / 800 hard). This is three small files.

**Gate after every phase:** `npm run build:ts && npm test && npm run lint && npm run smoke`.
Smoke fails on any renderer console error.

**Git:** one commit per phase, PR at the end, never commit to `develop`, no `Co-Authored-By`
trailer.

**Do not:**
- Do not call `setDatasetSteps` from the dock. Ever.
- Do not add a second thread store, transcript renderer, chart renderer, or context resolver.
- Do not let a model's output become a rendered number without passing through `copilot:ask`
  FACTS or `visual:data`.
- Do not apply anything automatically, chain proposals, or take a multi-step autonomous turn.
- Do not show the dock in presentation, focus, capture, published-read-only, or Explore.
- Do not use `innerHTML` for model text, or inline `style=` in hub HTML.
- Do not put dock state in `config.json` — it's view state.
- Do not add a runtime dependency.

## Task 1 — The shell

**Markup.** One `<aside id="dk-panel" class="dk-panel" hidden>` as the last child of `.hub-body`,
sibling to the `.ws-panels`. Inside: a header (`Based on …` context line + "New conversation" +
close), `#dk-messages`, and a composer (`#dk-input`, `#dk-send`) — same anatomy as Explore's,
scaled down.

**Layout.** `.hub-body` is already `display: flex`, so this is `flex: 0 0 340px` with
`min-width: 0` on the panel and its content. It pushes, it doesn't overlay — until
`max-width: 1100px`, where it becomes an overlay with a scrim so the canvas isn't crushed.

Beware `hub.css:4665`: `.hub-body:not([data-section="sources"]) .sidebar, … .main { display: none }`.
The dock must not be caught by those selectors. Verify it survives the Sources section
specifically.

**Toggle.**
- `#side-ai-btn` in the sidebar bottom opens it (it currently calls `selectSection('ai')` —
  repoint it).
- Keyboard: ⌘L / Ctrl+L, on a document keydown listener. Guard against firing while a text field
  is focused (`INPUT`, `TEXTAREA`, `[contenteditable]`). **Verified: no existing ⌘L accelerator in
  `main.ts` or any renderer file — ⌘L is free, use it.**
- State lives in `localStorage` (`dkOpen`, `dkWidth`) — renderer view state, not `config.json`.

**Where the dock is suppressed** — forced closed, toggle hidden, no exceptions:

| Condition | Why |
|-----------|-----|
| `body.dash-presenting` | presentation mode shows no chrome |
| `body.an-focus` | the analyses workbench already owns the full width |
| `body.cap-focus` | the capture surface is deliberately bare |
| `[data-section="explore"]` | Explore is the chat — two would be absurd |
| a published read-only dashboard (`dashReadOnly`) | nothing there is editable |

Implement as one `dkAllowed()` predicate called from `selectSection` and from the body-class
togglers. One rule, one place.

**Resize gotcha — do not skip.** Opening or closing the dock changes the canvas width. Chart.js
needs a resize nudge and MapLibre needs an explicit `map.resize()`; neither happens automatically
inside a flex sibling change. Wire that in this phase while the panel is still empty, so you find
it now instead of debugging a squashed chart in Task 3.

**Done when:** it opens and closes from both entries, pushes the layout without breaking any
section, stays closed where it should, survives a reload, and charts/maps reflow cleanly.
Composer inert.

**Verify:** `npm run build:ts && npm test && npm run lint && npm run smoke`.

## Task 2 — The conversation

**Context is implicit.** Call `buildCopilotContextRef()` with no override — that's the whole point
of the dock. Render the result in the header (`Based on dataset · Sales 2026` + the stats
app-computed chip) and re-render it on every `selectSection` and every entity open/close, so the
scope is never stale. A dock that claims the wrong context is worse than no dock.

**Send.** Reuse Explore's send path with `#dk-messages` as the container — same optimistic bubble,
same rebuild-from-disk on success, same `notReady` hint, same restore-the-text-on-failure. One
code path, two containers.

**One conversation.** The dock and Explore share the thread (and, once `feat/explore-threads`
lands, the same thread list). Ask in the dock, open Explore, and the conversation continues. Do
not add a second history store.

**Done when:** you can open a visual, ask "why did this dip in March", and get a grounded answer
with provenance; navigate to Explore and see the same conversation.

**Verify:** `npm run build:ts && npm test && npm run lint && npm run smoke`.

## Task 3 — Proposals you can apply

The reason the dock exists. Three types, each already backed by an IPC channel.

**The proposal card.** Rendered in the transcript below the assistant's text: a title, a
plain-English summary (reuse `stepSummaryText()` — don't write a second summariser), and two
buttons: **Apply** and **Dismiss**. One proposal per turn. Never a gallery.

**1. Prepare step — `dataset:suggestSteps`**

Offered when a dataset is the context and the answer implies a data fix ("412 rows have a blank
region").

⚠️ **Apply means `addDatasetStep`. Never `setDatasetSteps`.** `applySuggestedSteps()` in
`prepare.ts:680` calls `setDatasetSteps`, which replaces the entire pipeline. That is correct in
its flow (a confirmed full-pipeline suggestion) and catastrophic in this one — a dock suggestion
would silently delete every step the user built. Append one step with
`window.hub.addDatasetStep(projectId, datasetId, step)`.

After a successful apply: refresh the prepare rail (`renderStepsList` / `resetPreparePanel`), and
show inline confirmation — "Added as step 4. Remove it in Prepare to undo." Because
`transforms.ts` folds ordered steps over an immutable source, `removeDatasetStep(index)`
recomputes from source and leaves no residue. That's the undo; don't build another.

**2. Calculated field — `dataset:suggestCalcField`**

Apply does not apply. Match the existing behaviour exactly: open the step editor prefilled and let
the user Save. A formula is the one proposal a person should read before it lands, and
`formula.ts` compiles it — never `eval`, never `new Function`.

**3. A chart — `visual:suggest`**

Offered when the question is chart-shaped and a dataset is in scope. Compute with
`computeVisualData(projectId, datasetId, encoding, filters)` — never from anything the model
returned — and draw with the same path `renderVisualCard` uses. Under it: **Save as visual** (name
defaults to the question, truncated) and **Add to dashboard**, reusing `vizGallery.ts`'s existing
chooser.

**Rules for all three:**
- A proposal only appears when its context supports it. No dataset in scope → no step proposals,
  silently.
- `notReady` or a failed suggestion is silent. The text answer already stands; a proposal is a
  bonus, never an error.
- Dismiss leaves no trace.
- Nothing is ever applied without a click.

**Test:** a `scripts/test-*.js` self-check that a proposed step appended to a three-step pipeline
yields four steps in order, and that removing it returns the exact original result — `Object.is`
against the pre-apply output. That's the reversibility claim, pinned.

**Done when:** a suggested filter applies as an appended step visible in Prepare, removing it
restores the original data exactly, and a chart proposal saves into Visuals correctly.

**Verify:** `npm run build:ts && npm test && npm run lint && npm run smoke`.

## Task 4 — Resize and finish

- Drag handle on the dock's left edge. Min 300px, max 40% of window. Persist to `localStorage`.
  Keyboard-accessible (arrow keys on a focused handle) — a mouse-only resize fails accessibility
  basics.
- Re-run the chart/map resize nudge from Task 1 on drag end, not on every frame.
- Focus management: opening focuses the input; Esc closes and returns focus to the toggle.
- `aria-label` on the panel, `aria-expanded` on the toggle.

**Verify:** `npm run build:ts && npm test && npm run lint && npm run smoke`. Plus a real-app walk
across the suppression conditions and a reload-persistence check.
